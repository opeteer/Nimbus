# 🛠️ Audit Kesenjangan Teknis & Panduan Perbaikan `infra-ServerProject`

> **Dokumen Panduan Teknis untuk Agen Pengembang / DevOps**:
> Dokumen ini memuat temuan kritis, analisis celah teknis (*technical debt & bugs*), serta spesifikasi perbaikan konkret pada infrastruktur **`infra-ServerProject`** agar platform tersebut benar-benar siap mendukung aplikasi kompleks, *stateful*, dan berbasis *WebSocket* (seperti Nimbus) tanpa menimbulkan kerusakan konfigurasi (*zero regression*).

---

## 📌 Ringkasan Eksekutif Masalah

Pembaruan terkini pada `infra-ServerProject` memperkenalkan **Rocky Provisioning Bot API** (`bot.py` port `8090`) dan skrip automasi [`register-app.py`](file:///home/opeteer/infra-ServerProject/register-app.py). Meskipun inovasi ini sangat bagus untuk otomatisasi *Zero-Touch*, implementasi saat ini memiliki **celah destruktif fatal**:

1. **Destructive Compose Overwrite**: Skrip [`register-app.py`](file:///home/opeteer/infra-ServerProject/register-app.py) secara agresif menimpa entri service di [`compose.yaml`](file:///home/opeteer/infra-ServerProject/compose.yaml), sehingga **menghapus volume persisten** (`volumes:`), **variabel environment tambahan** (`environment:`), **kredensial database**, dan **seluruh komentar dokumentasi YAML**.
2. **Degradasi Konfigurasi Nginx**: Skrip membuat file `conf.d/routes/<app>.conf` dengan konfigurasi proxy HTTP dasar yang **tidak mendukung WebSocket** (`Upgrade`/`Connection`), **tidak memiliki trailing slash redirect**, dan **tidak memiliki timeout/buffer streaming** (membatasi upload/download file besar).
3. **Payload Bot yang Sangat Terbatas**: [`bot.py`](file:///home/opeteer/infra-ServerProject/bot.py) hanya menerima parameter minimal (`name`, `image`, `port`, `path`, `icon`, `desc`, `tags`), dan sama sekali tidak bisa menerima deklarasi `volumes`, `environment`, maupun flag `websocket`.
4. **Race Condition & Lack of Concurrency Lock**: Jika dua GitHub Actions melakukan push bersamaan, dua proses `register-app.py` dapat menulis [`compose.yaml`](file:///home/opeteer/infra-ServerProject/compose.yaml) secara bersamaan dan merusak file (*file corruption*).

## 🔍 Rincian Masalah Teknis & Lokasi File

---

### 1. File: `infra-ServerProject/register-app.py`

#### A. Masalah: Menghapus Volume dan Environment yang Sudah Ada
* **Lokasi Kode**: Baris 37–54
```python
def update_compose(app_name: str, image: str, port: int):
    with open(COMPOSE_FILE, 'r') as f:
        data = yaml.safe_load(f) or {}

    if 'services' not in data:
        data['services'] = {}

    container_name = f"{app_name}-web"
    service_def = {
        'image': image,
        'container_name': container_name,
        'restart': 'unless-stopped',
        'networks': ['server-net'],
        'environment': [f"PORT={port}"],
        'labels': ["com.centurylinklabs.watchtower.enable=true"]
    }

    data['services'][app_name] = service_def  # ❌ FATAL: Menimpa objek lama secara mentah!
```
* **Dampak**: 
  * Pada aplikasi seperti **Nimbus**, konfigurasi `volumes: [nimbus_downloads:/app/downloads]` dan `NIMBUS_PASSWORD=...` langsung terhapus saat bot dipicu.
  * Pada aplikasi dengan database, data akan hilang saat kontainer di-recreate tanpa volume.
* **Solusi yang Harus Diterapkan Agen**:
  * Lakukan *smart merge*. Jika service `app_name` sudah ada di `data['services']`, pertahankan nilai `volumes`, `environment` yang sudah ada, `depends_on`, `healthcheck`, dan `restart`.
  * Tambahkan parameter opsional `volumes: list = None` dan `env_vars: list = None` pada fungsi `update_compose`.
  * Pastikan named volume di tingkat root `volumes:` juga didaftarkan jika ada volume baru yang memerlukan persistent storage.

#### B. Masalah: Hilangnya Komentar YAML karena `yaml.dump` Standar
* **Lokasi Kode**: Baris 62–63
```python
with open(COMPOSE_FILE, 'w') as f:
    yaml.dump(data, f, default_flow_style=False, sort_keys=False)
```
* **Dampak**: `yaml.dump` dari pustaka PyYAML standar membuang seluruh baris komentar (`# ==================`), merestrukturisasi urutan hierarki, dan membuat file `compose.yaml` berantakan.
* **Solusi yang Harus Diterapkan Agen**:
  * Gunakan pustaka `ruamel.yaml` (jika tersedia) ATAU buat parser non-destruktif / merge aman yang memelihara struktur file.

---

#### C. Masalah: Template Nginx Tidak Mendukung WebSocket dan Streaming Media
* **Lokasi Kode**: Baris 65–85
```python
def create_nginx_route(app_name: str, subpath: str, port: int):
    ...
    content = f"""# ==============================================================================
# Route Plug-in: {app_name} (Auto-generated by register-app)
# ==============================================================================

location {subpath} {{
    proxy_pass http://{container_name}:{port}/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Prefix {subpath.rstrip('/')};
}}
"""
```
* **Dampak**:
  1. **WebSocket Putus**: Tidak ada header `proxy_http_version 1.1`, `Upgrade`, dan `Connection "upgrade"`. Progress bar real-time Nimbus atau aplikasi Socket.IO langsung lumpuh.
  2. **404 pada URL tanpa Trailing Slash**: Jika user membuka `/nimbus`, gateway akan 404 karena tidak ada redirect `location = /nimbus { return 301 /nimbus/; }`.
  3. **Timeout Pengunduhan Besar**: Tidak ada `proxy_buffering off;`, `client_max_body_size 500M;`, dan `proxy_read_timeout 600s;`. Pengunduhan video/file besar akan putus di tengah jalan.
  4. **Menimpa File Kustom**: Jika developer sudah menyetel file `conf.d/routes/<app>.conf` secara manual dengan konfigurasi khusus, file tersebut ditimpa paksa.
* **Solusi yang Harus Diterapkan Agen**:
  * Cek apakah `conf_path` sudah ada. Jika sudah ada, **JANGAN TIMPA** kecuali diberikan flag `--force`.
  * Tambahkan parameter `--websocket` (atau flag boolean `websocket=True`). Jika aktif, suntikkan blok WebSocket headers, buffering off, dan timeout streaming secara otomatis.
  * Tambahkan blok normalisasi trailing slash:
    ```nginx
    location = {subpath.rstrip('/')} {{
        return 301 {subpath};
    }}
    ```

### 2. File: `infra-ServerProject/bot.py`

#### A. Masalah: Kurangnya Parameter Payload & Parsing Data
* **Lokasi Kode**: Baris 103–124
* **Dampak**: Bot tidak dapat menerima konfigurasi `volumes`, `env`, `websocket`, maupun flag optimasi lainnya dari payload GitHub Actions.
* **Solusi yang Harus Diterapkan Agen**:
  * Tambahkan penangkapan field dari JSON payload:
    ```python
    websocket = payload.get('websocket', False)
    volumes = payload.get('volumes', [])
    custom_env = payload.get('env', []) or payload.get('environment', [])
    ```
  * Teruskan parameter tersebut sebagai argumen CLI ke `register-app.py`.

#### B. Masalah: Potensi Concurrency Race Condition
* **Lokasi Kode**: Baris 140–158
* **Dampak**: Jika ada 2 repo yang push bersamaan, dua thread `ProvisionRequestHandler` akan menjalankan `register-app.py` dan memanipulasi `compose.yaml` bersamaan.
* **Solusi yang Harus Diterapkan Agen**:
  * Gunakan `threading.Lock()` atau file lock (`fcntl.flock`) di `bot.py` saat mengeksekusi proses registrasi agar eksekusi berlangsung antre (*atomic & sequential*).

---

### 3. File: `infra-ServerProject/nginx.conf`

#### Masalah: Belum Ada Map Connection Upgrade untuk WebSocket
* **Lokasi Kode**: Blok `http {}`
* **Dampak**: Jika proxy meneruskan header `$http_upgrade` tanpa map connection, beberapa client WebSocket dengan header non-standar dapat ditolak oleh Nginx.
* **Solusi yang Harus Diterapkan Agen**:
  * Tambahkan pemetaan connection upgrade standar di dalam blok `http {}`:
    ```nginx
    map $http_upgrade $connection_upgrade {
        default upgrade;
        ''      close;
    }
    ```

## 🎯 Spesifikasi Rincian Perbaikan yang Harus Dikerjakan Agen Lain

Agen yang bertugas memperbaiki `infra-ServerProject` harus memenuhi checklist berikut:

### Checklist Tugas Agen:

- [ ] **1. Perbarui `register-app.py`**:
  - [ ] Tambahkan argumen CLI:
    - `--websocket` (flag untuk mengaktifkan WebSocket support pada Nginx route).
    - `--volume` / `-v` (`action='append'`, daftar volume persisten, misal `nimbus_downloads:/app/downloads`).
    - `--env` / `-e` (`action='append'`, daftar environment variables tambahan, misal `NIMBUS_PASSWORD=secret`).
    - `--preserve` (default: `True`, mempertahankan konfigurasi compose & route yang sudah ada jika app sudah terdaftar).
  - [ ] Perbaiki fungsi `update_compose`:
    - Baca service lama jika ada: `existing = data['services'].get(app_name, {})`.
    - Lakukan merge `volumes = list(set(existing.get('volumes', []) + new_volumes))`.
    - Lakukan merge `environment`.
    - Jika ada named volume baru, tambahkan ke blok root `volumes:`.
  - [ ] Perbaiki fungsi `create_nginx_route`:
    - Jangan timpa file jika sudah ada (kecuali `--force`).
    - Jika `--websocket` aktif, masukkan `proxy_http_version 1.1`, header `Upgrade`, `Connection "upgrade"`, `proxy_buffering off`, dan timeout streaming 600s.
    - Sertakan redirect normalisasi trailing slash `location = /<app> { return 301 /<app>/; }`.

- [ ] **2. Perbarui `bot.py`**:
  - [ ] Pasang `threading.Lock()` global untuk memblokir race condition pada pemanggilan `register-app.py`.
  - [ ] Parse field `websocket` (bool), `volumes` (list), dan `env` (list) dari JSON body.
  - [ ] Operkan parameter tersebut ke pemanggilan `subprocess` `register-app.py`.

- [ ] **3. Perbarui `nginx.conf`**:
  - [ ] Tambahkan `map $http_upgrade $connection_upgrade` di blok `http`.

- [ ] **4. Uji Verifikasi**:
  - [ ] Jalankan simulasi:
    ```bash
    python3 register-app.py --name nimbus --image ghcr.io/opeteer/nimbus:latest --port 8000 --websocket --json-output
    ```
  - [ ] Pastikan file `compose.yaml` TIDAK kehilangan volume `nimbus_downloads` dan variabel `NIMBUS_PASSWORD`.
  - [ ] Pastikan `conf.d/routes/nimbus.conf` TIDAK kehilangan dukungan WebSocket dan timeout streaming.
